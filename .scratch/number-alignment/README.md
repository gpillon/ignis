# Raw material for GitHub #254

`width_probe.py` asks the same four truths at every width in `DIGITS` and
keeps the whole per-digit trace. `pad_probe.py` is the same walk with the
alignment rule appended to the caller's own `instructions` — the zero-code
probe that established the ambiguity was prompt-level before a line of
`number_system` was touched.

`width-probe-after.jsonl` is the walk **after** the clause shipped. The run
before it is not here: the probe overwrites its own output, and by the time
the fix was confirmed the earlier file was gone. Both tables are in the
finding, which is where the comparison belongs anyway.
