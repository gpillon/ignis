# The kernels the release's CUDA build check holds to the full-rate rule on the
# `86` cubin (GitHub #503, #512): mk/cuda-build-check.sh reads this file, and
# nothing else says which kernels the rule covers. One kernel, one line:
#
#   <role>  <kernel name>  [<source file>]   # why
#
# The name is the function's own name, without its template arguments, so every
# instantiation is held to the rule. The roles:
#
#   mma      a GEMM or band kernel. Refused: HMMA with an f32 accumulator, any
#            BF16, TF32 or FP8/FP6/FP4 form, any warpgroup or tensor-memory MMA,
#            any MMA form not named below. Allowed: IMMA, and HMMA with an f16
#            accumulator (reported). Required: IMMA in each instantiation.
#   cuda     a kernel that runs on the CUDA cores: the same refusals, and no
#            MMA required.
#   exempt   a kernel that predates the rule and is left as it is. Never
#            refused, its MMA forms are reported. Each one names the issue that
#            decided it; a kernel leaves the list when that issue converts it.
#   control  the check's negative control: a kernel that does carry a forbidden
#            form. The check refuses a build in which it does not find one, so
#            a dump the check can no longer read is not a pass.
#
# A kernel in a covered role must be in the cubin of one of the binaries the
# check is given (a renamed or dropped kernel is refused, not skipped), and the
# tests hold every `__global__` function of each source file named here to a
# line of this file. A new kernel of the sm_8x prefill work joins with one line
# (docs/agents/testing.md, "A new kernel and the full-rate rule").
